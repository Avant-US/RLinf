# RLT Stage 2 部署指南（Franky 版）




## 模型输入与输出

### Stage 1（VLA / π₀.₅ 微调）

#### 输入

| 模态 | 维度 / 规格 | 说明 |
|------|------------|------|
| state | **19 维**（内部补零到 32 维） | gripper_position(1) + tcp_force(3) + tcp_pose(6, xyz+euler) + tcp_torque(3) + tcp_velocity(6, 线速度3+角速度3) |
| image | 224×224 RGB | global 相机 |
| wrist_image | 224×224 RGB | 手腕相机 |
| task description | 文本 | `"plug the plug into the socket"` |

#### 输出（训练标签 / 推理结果）

| 字段 | 维度 | 说明 |
|------|------|------|
| action | **20 × 7**（20 chunks，内部补零到 32 维） | `[dx, dy, dz, droll, dpitch, dyaw, gripper]` |

- 20 个 action chunks = 2 秒（10 Hz）
- 每步增量**相对于上一帧**（逐帧差分），不是相对于第一帧
- 位置增量归一化：除以 0.02 m
- 旋转增量归一化：除以 0.1 rad
- 夹爪：+1=张开、-1=闭合，裁剪到 [-1, 1]

### Stage 2（MLP actor-critic，Stage 1 冻结）

#### 冻结 Stage 1 特征模型产出

| 字段 | 维度 | 说明 |
|------|------|------|
| z_rl | 2048 | RLT 表示向量 |
| proprio | 19 | 原始 19 维 state（透传） |
| ref_chunk | 20 × 7 | VLA 给出的 20-step 参考动作 |

#### Stage 2 MLP actor

- **输入**：ref_chunk 前 10 步(10×7=70) + z_rl(2048) + proprio(19) = **2137 维**
  （冻结 VLA 产出 20-step ref_chunk，MLP 内部截断为前 10 步后 flatten 拼接）
- **输出**：

| 字段 | 维度 | 说明 |
|------|------|------|
| action | **10 × 7** | 10-step chunk = 1 秒，格式同 Stage 1 的 7 维末端增量动作 |

### 关键对齐约束

- **频率**：全链路 10 Hz
- **增量参考帧**：每步 delta 基于当前实测 TCP 位姿（`FrankaEnv.step()` 每步从 `self._franka_state.tcp_pose` 出发），与训练数据的逐帧差分语义一致。Franky 版不存在 `use_persistent_desired_pose`，不会累加未达到的位姿误差
- **坐标系**：基座坐标系 TCP delta（`use_relative_frame: false`）
- **夹爪方向**：当前 Stage 1 权重的训练数据夹爪写反了，在线部署靠 `invert_gripper_action` + `invert_gripper_width_obs` 两个开关补偿；重训后两个开关都改回 `false`
- **图像**：离线转换和在线都做中心正方形裁剪 → 224×224
- **action_scale**：位置 0.02 m、旋转 0.1 rad、夹爪阈值 ±0.3

### 夹爪全链路

#### FrankaEnv 的原始约定

`FrankaEnv._binary_gripper_action` 的判断逻辑：

```
action[6] <= -0.3  →  闭合夹爪
action[6] >= +0.3  →  打开夹爪
[-0.3, +0.3] 区间  →  保持不动
```

FrankaEnv 期望 **+1=张开、-1=闭合**。

#### 当前 Stage 1 权重实际学到的方向（反了）

老版转换脚本用了 `2*raw-1`（GELLO raw: `0=张开、1=闭合`），导致训练数据里方向反转：

| 物理状态 | GELLO raw | 训练动作值 | 本应是 |
|---------|-----------|-----------|-------|
| 夹爪张开 | 0 | **-1** | +1 |
| 夹爪闭合 | 1 | **+1** | -1 |

模型学到的是 **+1=闭合、-1=张开**，和 FrankaEnv 期望刚好相反。

#### 在线部署的修正

`invert_gripper_action=true` 在 `step()` 里把模型输出的第 7 维取负：

```
模型输出 +1（它认为闭合）→ 取负变成 -1 → FrankaEnv 收到 -1 → 闭合 ✓
模型输出 -1（它认为张开）→ 取负变成 +1 → FrankaEnv 收到 +1 → 张开 ✓
```

`invert_gripper_width_obs=true` 把 state 观测也做反向映射，让模型在线看到的
`gripper_position` 分布和训练时一致：

```
实测 0.08m（张开）→ 送给模型 0.01（训练时张开对应的值）
实测 0.00m（闭合）→ 送给模型 0.09（训练时闭合对应的值）
```

#### 数据流总表

| 层 | 夹爪值范围 | 闭合 | 张开 |
|----|-----------|------|------|
| **模型原始输出** | [-1, +1] | **+1** | **-1** |
| `invert_gripper_action` 取负后 | [-1, +1] | -1 | +1 |
| FrankaEnv 执行 | `<=-0.3` 闭合, `>=+0.3` 打开 | 闭合 | 打开 |

**对当前模型：输出接近 +1 代表闭合，输出接近 -1 代表张开。**
两个 `invert` 开关在运行时修正差异。用修正后的转换脚本重训 Stage 1 后，
两个开关都要改回 `false`。

> 模型看到 2 张 224×224 RGB + 19 维 state，Stage 1 输出 20×7 的 2 秒参考动作，Stage 2 在此基础上输出 10×7 的 1 秒执行动作，都是逐帧末端增量控制。












本指南将原 ROS 控制链路替换为 Franky（直接 libfranka），实现 RLT Stage 2
在线强化学习训练、策略推理和 SpaceMouse 遥操作接管。

## 与 ROS 版的区别

| 项目 | ROS 版 | Franky 版 |
|------|--------|-----------|
| 控制器 | `FrankaController` (roslaunch + impedance.launch) | `FrankyControllerExtended` (franky 0.19.0 直接 FCI) |
| Gym 环境 | `PegInsertionEnv-v1` | `FrankyPegInsertionEnv-v1` |
| 安全机制 | ROS 碰撞检测 | 多层防护（力限制 + 几何围栏 + 速度上限 + 看门狗） |
| 依赖 | ROS Noetic + franka_ros | franky-control 0.19.0 (libfranka >= 0.18) |
| 固件要求 | < 5.9.0 | >= 5.10.0（当前机器人） |
| 夹爪驱动 | franka_ros gripper | FrankaLibfrankaGripper (franky 原生) |
| 启动方式 | roslaunch | 直接 Python（无 ROS） |

## 8. 训练中操作

### 键盘控制（在 Franky 容器的键盘上操作）

| 按键 | 作用 |
|------|------|
| `b` | 从 VLA reference 切换到 Stage 2 actor 控制 |
| `c` | 标记成功 (reward=1)，结束当前 episode |
| `a` | 标记失败 (reward=0)，结束当前 episode |

每个 episode reset 后自动回到 VLA reference，需要再次按 `b`。

### SpaceMouse 遥操作接管

SpaceMouse 连续移动超过 0.5 秒时自动接管策略动作：
- **6D 摇杆**：xyz 平移 + roll/pitch/yaw 旋转
- **左键**：闭合夹爪
- **右键**：打开夹爪
- 松手 0.5 秒后自动还给策略

SpaceMouse 介入不受键盘 b/c/a 影响，在 VLA reference 和 Stage 2 actor
两个阶段都能使用。介入动作会覆盖当前策略输出。

### 典型 episode 流程

1. **reset**：尝试打开夹爪（空手容错） → 直接回到 target 位姿（无抬升）
2. **VLA reference**（未按 b）：冻结 Stage 1 模型执行参考动作
3. **SpaceMouse 可随时介入**纠正位姿
4. 操作员判断进入精密阶段后按 **b**
5. **Stage 2 actor** 控制，transition 写入 replay
6. 成功按 **c**（reward=1），失败按 **a**（reward=0）
7. 下一个 episode 自动 reset

任务流程：夹爪打开 → 伸向充电头 → 夹住 → 插入插排 → 放开

## 9. 监控指标

日志输出到 `b/rlt/results/<timestamp>/`。关键指标：

```text
train/replay_buffer/size   — 按 b 后才增加
critic/critic_loss          — critic 收敛情况
actor/actor_loss            — actor 训练情况
actor/bc_loss               — 对 reference 的 BC 损失
q_pi                        — actor 预期 Q 值
env/episode_len             — episode 长度
```

`[ActionDebug]` 日志可辅助调试动作裁剪与实际执行差异。

## 12. 常见问题

### FCI 连接被拒绝

```text
franky.errors.IncompatibleLibraryVersionError
```

检查：
1. Franka Desk 中 FCI 已开启
2. 没有其他 libfranka / ROS 进程占用机器人
3. 固件版本 >= 5.10.0

### SpaceMouse 无反应

1. 确认 `ls /dev/input/event*` 显示设备
2. 确认 Docker 启动时带 `--privileged`
3. 确认 `pip install pyspacemouse` 已安装
4. 运行 `python b/rlt/scripts/test_spacemouse.py` 排查

### replay_buffer/size 一直为 0

- 确认在 Franky 容器键盘上按了 `b`
- 检查日志是否出现 `Pedal 'b' pressed; switching RLT rollout to Stage2 actor.`
- 确认 `RLINF_KEYBOARD_DEVICE` 指向正确设备

### 安全围栏触发

```text
Motion guard tripped: fence [...]
```

- 检查 `target_ee_pose` 和 `safety_box_half_width_m` 是否合理
- 训练自动恢复（budget=10），超出后 episode 结束
- 紧急情况直接按 Franka 急停按钮
