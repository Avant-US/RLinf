## 0. 分类方法论

### 0.1 为什么不能用"一个条目对应一个类别"

同一条信息在仿真和真实两端的地位往往不同。最典型的例子是深度图：仿真里渲染器直接吐出无噪声的完美真值（属于问题一），真实里既可以用 RGB-D 硬件直接测量（有噪声，仍属"直接拿到"），也可以用单目深度估计模型算出一个伪标签（属于问题三）。如果把"深度"整体归到某一类，就会丢失这个关键差异——而这个差异恰恰是 [方法学审稿](./d4a_geometry_4d_ab_methodology_review.md) 里 **C6"仿真深度是完美深度"** 这条混淆因素、以及 [监督调研](./d4a_training_supervision_survey.md) **§5"仿真真值 vs 伪标签"** 一节的核心论点。

因此本文档采用：**§1 主表逐条目分别标注仿真侧与真实侧的获取方式**，然后 §2–§4 分别摘出对应用户三问的条目清单（同一条目可能在两问里都出现，比如"深度"既在问题一的清单里，也在问题三的清单里——因为它在仿真端是问题一，在真实端是问题三）。

### 0.2 问题三的两个必须分开的子类型

文档原文（尤其主方案 §7.2 的伪标签流水线）把计算方式明确分成"解析支路"和"学习支路"两条并行管线，这个区分不是随意的，混在一起会误导对精度与成本的判断：

| 子类型 | 定义 | 误差特性 | 是否区分仿真/真实 | 代表条目 |
|---|---|---|---|---|
| **3a 解析 / 运动学计算** | 由已知量（关节角、URDF、标定参数）通过确定性几何公式算出，不涉及任何学习模型 | **零误差**（前提：URDF 与标定准确）——精度只取决于输入量的精度，不取决于"计算"这一步本身 | **不区分**：仿真和真实用同一套公式，只要关节角和标定已知 | 相机外参（FK）、pointmap（深度+外参反投影）、ray map、ego-flow、自碰撞距离、swept volume、双臂相对位姿 |
| **3b 统计 / 学习估计（伪标签）** | 由神经网络模型从原始观测（图像/视频）推断出，本身是一个近似 | **有噪声**，且噪声结构随模型/版本变化 | **主要针对真实环境**：仿真中对应量往往是免费真值，无需 3b | 单目深度估计、光流网络、分割网络、点跟踪、多视角几何基础模型、物体 6-DoF 位姿跟踪、接触事件启发式反标注 |
| **状态估计 / 滤波积分**（介于两者之间） | 对含噪测量做时间上的递推融合（如卡尔曼滤波、里程计积分、SLAM 建图） | **有漂移**，随时间累积，但不是"看图猜"意义上的学习伪标签 | **主要针对真实环境**：仿真中对应量（如基座世界位姿）可直接读取模拟器内部状态 | 轮式里程计+IMU 融合、视觉里程计/SLAM、TSDF 持久空间记忆融合 |

后文用 **【3a】【3b】【状态估计】** 三个标签标注每条属于问题三的信息。

### 0.3 阅读约定

- 主表每行格式：**信息条目 \| 仿真侧获取方式 \| 真实侧获取方式 \| 真实侧类别与计算方法 \| 来源**。
- "来源"列引用文件简称与章节号，可用于回查原文的完整论证与数值。
- 本文档不引入代码库之外的新论文或新结论，只做**忠实提炼与重组**，因此不使用原文档的 🟢/🟡/⚪/[D] 可靠性标注体系。

## 2. 问题一的答案：仅仿真可得 GT、真实环境结构性拿不到

以下条目不是"真实环境暂时测不准"，而是**没有对应传感器、或需要昂贵专用设备**（如动作捕捉系统）才能获得近似替代，与仿真里"读取内部状态"这种精确度不在同一量级：

| 条目 | 为什么真实环境结构性拿不到 | 对应条目编号 |
|---|---|---|
| 完美无噪声深度/分割/光流/法线（作为"真值"这个理想量本身） | 真实传感器有物理噪声下限（反光、透明物体失效、边缘飞点），估计模型有算法误差；"零噪声"这件事在真实里不存在 | #6, #7, #13, #14 |
| 物体精确材质/摩擦系数/质量/惯性参数 | 没有便携、低成本、能在操作现场实时测量这些量的传感器；系统辨识需要专门实验且精度远不及仿真配置值 | #16, #34（$m_{\text{mat}}$ 分量） |
| 物体精确形状/尺寸参数（$s_{\text{shape}}$） | 同上，量化后的形状 box 是仿真资产的元数据，真实物体没有这个"标签" | #34（$s_{\text{shape}}$ 分量） |
| 光照参数 $l$（作为标量/向量的精确光照描述） | 真实场景的光照是连续、非参数化的物理现象，没有"光照真值向量"这个对象 | #34（$l$ 分量） |
| 精确的、无漂移的基座世界系绝对位姿 | 真实世界没有"上帝视角"，只能靠里程计/SLAM 估计，必然有漂移；仿真里模拟器直接维护这个状态 | #3, #26 |
| 物理引擎接触求解器给出的精确接触标志与接触力 | 真实环境中，力/触觉传感器被排除在本方案范围外，只能用视觉间接推断（有噪声、有滞后），且推断不出"力"本身，只能推断"是否接触" | #28 |
| 域随机化几何参数（桌面高度、clutter 等抽象标量） | 这些是仿真场景生成器的配置参数，真实世界没有与之对应的显式变量，只能从观测间接感知，不构成同一个可比较的数值 | #19 |
| RoboTwin 特权 API（`functional_point`/`target_point`/`contact_point`/`orientation_point`） | 这些是仿真任务定义时人工写入资产元数据的标注点，真实物体没有这个附加信息，需要额外的可供性检测或人工标注才能获得近似替代 | #17 |
| 物体 6-DoF 位姿的"零抖动"版本 | 真实姿态跟踪（FoundationPose 等）存在帧间抖动与遮挡失效，仿真中直接读取物理引擎状态没有这个问题 | #15 |
| 稠密全场景 3D 点轨迹的"完美"版本（ELAN4D 上界实验用的那种） | 真实点跟踪器（CoTracker3 等）在无纹理表面、遮挡、快速运动下会跟丢，仿真直接用物体真值位姿采样 mesh 点没有这个问题 | #30 |

**一条重要的方法学提醒**（来自 [方法学审稿](./d4a_geometry_4d_ab_methodology_review.md) C5）：如果实验设计中让"几何臂"能访问上表中的任意一项，而"基线臂"访问不到，测出来的收益很可能是**特权信息泄漏**而非"几何本身有用"——DP3 去掉裁剪框（一种特权信息）就掉 11.9 个百分点，说明这类信息的边际价值可能被严重高估。

## 3. 问题二的答案：两端都可直接拿到

以下条目**不需要额外的计算/估计模型**，两端都可以通过传感器/配置直接读出（可能仍有测量噪声，但获取方式本身是"读"而不是"算"或"猜"）：

| 条目 | 仿真侧获取方式 | 真实侧获取方式 | 对应条目编号 |
|---|---|---|---|
| RGB 图像 $I_t^{(v)}$ | 渲染器直出 | 相机直接采集 | 主方案 §1.1.2 |
| 关节角 $q$、关节速度 $\dot q$ | 模拟器状态 | 编码器直接测量 | #20 |
| 夹爪开度 $g^{\text{L}}, g^{\text{R}}$ | 模拟器状态 | 编码器/电位计直接测量 | #23 |
| 相机内参 $K$（一次标定后视为常量） | 场景配置直接给出 | 一次性标定后固定使用 | #1 |
| 语言指令 $\ell$ | 任务定义直接给出 | 人工输入 | #39 |
| 图像与关节状态的时间戳 | 天然同步 | 硬件时钟打戳 | #4 |
| 物体 6-DoF 位姿（仅指仿真侧，作为对照） | **模拟器/任务 API 直接给出** | （真实侧不属于本类，见问题三/问题一） | #15 |

> 注意：这一类条目数量比问题一、问题三少得多——这正是文档反复强调的核心矛盾：**大多数"有用的几何/4D 信息"在仿真里免费，但恰恰不属于"两端都能直接拿到"这一类**，真实环境要么需要专用硬件（RGB-D 传感器，仍有噪声）要么需要计算/估计（问题三）。

## 4. 问题三的答案：需要计算才能得到类 GT 值，及具体计算方法

### 4.1 子表 A ——【3a 解析/运动学计算】（零误差，两端同一套公式）

这一类是本方案反复强调的"免费午餐"：只要关节角、URDF、标定参数已知（这些本身属于问题二的直接可得项），后续计算是确定性几何/运动学运算，**没有额外误差引入**，在仿真和真实中精度相同。

| 条目 | 计算方法 | 关键公式/算法 | 来源 |
|---|---|---|---|
| 相机外参 | 前向运动学（FK）+ URDF | $T_{\text{base}\leftarrow\text{cam}} = \text{FK}(q, \text{URDF})$ | 主方案 §3.2、§3.4(a) |
| Pointmap | 深度 + 外参逐像素反投影 | $P = T_{\text{base}\leftarrow\text{cam}} \cdot \pi^{-1}(u, D)$ | 主方案 §3.2.1 |
| Ray map | FK + 相机内参 | $\mathbf{r}_{\text{base}} = R_{\text{base}\leftarrow\text{cam}} \cdot \text{normalize}(K^{-1}[u_x,u_y,1]^\top)$，配 6 维 $(\mathbf{o}_{\text{base}}, \mathbf{r}_{\text{base}})$ | 主方案 §3.4(a)、附录"四" |
| Ego-flow | 已知相机位姿变化 $\Delta T$ + 深度 $D_t$ 逐像素重投影 | $u' = \pi(\Delta T \cdot \pi^{-1}(u, D_t))$，$f_{\text{ego}} = u' - u$ | 主方案 §3.3#3 |
| 全身自遮挡掩膜/本体深度 | URDF + 全关节角 + 可微渲染 | nvdiffrast / PyTorch3D 渲染 | 主方案 §3.3#2、§7.2[A3] |
| 自碰撞距离场 | URDF 连杆用胶囊体近似，取几何最近距离 | 胶囊体-胶囊体最近距离查询 | 主方案 §3.3#12 |
| 全身未来 swept volume | 预测动作 → 基座运动学积分 + FK → 连杆位姿序列 → URDF mesh → 沿时间做体素并集 | $\text{SweptVolume} = \bigcup_{i=0}^{H-1} \text{Occupy}(\text{Robot}, \text{pose}(t+i))$ | 主方案 §4.3、附录"一" |
| 末端执行器位姿/双臂相对位姿 | FK 计算 + 两位姿相减 | $\text{FK}(q)$，$T^{\text{ee,L}\leftarrow\text{ee,R}} = (T^{\text{ee,R}})^{-1} T^{\text{ee,L}}$ | 主方案 §1.1.2、§3.5 |

| 标定漂移监控 | 已知位置的本体连杆特征投影回图像，测重投影误差 | $\| \Pi_v(P_{\text{known}}) - u_{\text{observed}} \|$ | 主方案 §3.8 |

## 5. 交叉案例：完整串讲"仿真免费 → 真实计算"的链路

以下四个信息在文档中反复出现，是"问题一"与"问题三"在同一条目上的两个侧面，完整走一遍链路有助于理解为什么二者要分开讨论。

### 案例 1：度量深度图

- **仿真侧（问题一/直接拿到）**：渲染器直接输出深度缓冲区，无噪声、无空洞、无反光失效、无标定误差（主方案 §7.4）。
- **真实侧路径 A（问题二/直接拿到）**：RGB-D 硬件直接测量，但有噪声与空洞，尤其在反光、透明、细小物体上失效。
- **真实侧路径 B（问题三/3b 学习估计）**：跑单目度量深度模型（Depth Anything 3 Metric / Metric3D / MoGe），输出一个"类真值"深度，存在尺度与边缘误差。
- **下游影响**：[监督调研](./d4a_training_supervision_survey.md) §5.2 指出，GeoPredict 用仿真真值深度 + 可微渲染得到 +7.1pt 收益，而 DreamVLA 用伪标签深度反而观察到性能下降——最可能的解释就是"真值 vs 伪标签"的差别本身，而不是"深度这个模态没用"。这说明**同一个信息条目，获取方式不同（问题一 vs 问题三），下游效果可能完全相反**。

### 案例 2：实例分割掩膜

- **仿真侧**：渲染器直出完美 segmentation mask，物体/部件边界精确，跨帧 ID 一致。
- **真实侧**：SAM2 / Grounded-SAM 用指令名词做 prompt 估计，边界不精确，需要额外的跨帧跟踪逻辑维持 ID 一致性；掩膜质量直接影响下游的物体 6-DoF 拟合（案例 3）与接触事件反标注。

### 案例 3：物体 6-DoF 位姿及未来轨迹

- **仿真侧**：物理引擎/任务 API（如 RoboTwin 的 `actor.get_pose()`）直接给出精确位姿，无抖动。ELAN4D 的"上界实验"正是利用这一点：直接用仿真器真值物体关键点做全场景 4D 监督。
- **真实侧**：两条计算路径——(a) FoundationPose / BundleSDF 直接做位姿跟踪；(b) 先用点跟踪模型（CoTracker3 等）拿到 2D/3D 长时轨迹，再用 Procrustes / PnP 刚体拟合解出 $SE(3)$ 轨迹（Track2Act 的做法）。两条路径都会因遮挡、快速运动引入抖动或跟丢。
- **一个反直觉的发现**：ELAN4D 的上界实验显示，"全场景真值轨迹"（79.3%）相比"只监督机器人自身 FK 关键点"（78.2%，纯【3a 解析】、零成本）只高 1.1 个百分点，而预处理成本高约 240 倍（监督调研 §1.3 B-1、§5.1）。这意味着在很多场景下，**用零成本的 3a 解析信息（本体 FK 轨迹）替代昂贵的 3b 学习估计信息（全场景物体轨迹），收益损失很小**。

### 案例 4：光流/场景流

- **仿真侧**：渲染器可直接输出真值光流；也可以用 #12 的解析 ego-flow 公式，基于真值深度和已知相机位姿变化算出"假设场景静止时应该看到的光流"，二者理论上应一致。
- **真实侧**：观测光流 $F_{\text{obs}}$ 必须用 RAFT 系模型估计（3b），再减去解析计算的 ego-flow（3a）得到残差流 $F_{\text{residual}} = F_{\text{obs}} - F_{\text{ego}}$——这是"3a 解析"与"3b 学习估计"在同一条流水线里协作的典型例子：**已知的自运动部分用解析计算精确扣除，未知的场景运动部分才交给学习模型**，而不是让模型从头学习"哪些运动是我自己造成的"。

|---|---|---|---|
| **问题一：仅仿真可得 GT** | 10 | 完美深度/分割/光流、物体材质/形状/光照、精确无漂移基座位姿、物理引擎接触标志、RoboTwin 特权 API | 仿真器内部状态或渲染器直出，真实环境没有对应的零误差获取手段，只能用更差的近似替代 |
| **问题二：两端都可直接拿到** | 7 | RGB 图像、关节角/关节速度、夹爪开度、相机内参、语言指令、时间戳 | 传感器直接读数或任务直接给定，不涉及额外的估计或复杂计算 |
| **问题三 · 3a 解析计算** | 10 | 相机外参、pointmap、ray map、ego-flow、自碰撞距离、swept volume | 由已知量通过确定性几何/运动学公式算出，零误差，仿真真实通用同一套公式 |
| **问题三 · 3b 学习估计（伪标签）** | 13 | 单目深度、光流、分割、点跟踪、物体位姿跟踪、接触事件反标注、可供性检测 | 用神经网络模型从图像/视频推断，替代仿真中免费的真值，天然带噪声，需质量门控 |
| **问题三 · 状态估计/滤波积分** | 3 | 基座里程计、持久空间记忆融合、标定漂移修正 | 对含噪测量做时间递推融合，随时间累积漂移，介于解析与学习估计之间 |

**核心结论**（呼应 [监督调研](./d4a_training_supervision_survey.md) §5.2 的成本对比表）：仿真环境把"深度/掩膜/分割/全场景点轨迹"这一整档信息从"真机中需要昂贵伪标签流水线（成本比可达 1:30 至 1:240）"直接降到"零成本免费真值"，这是仿真相对真实环境最大的结构性优势；而"本体解析类"信息（FK 轨迹、外参、自碰撞、swept volume）在两端成本都接近零，是唯一一类不受"仿真 vs 真实"影响的信息来源。这也是为什么 [MVPA 方案](./d4a_solutioin_1_c_mvpa.md) §3.4 把 P3a（FK 本体关键点轨迹）列为验证优先级最高的路线——它是清单中**唯一同时满足"零成本"与"仿真真实通用"两个条件**的信息条目。
