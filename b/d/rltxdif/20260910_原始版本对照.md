## 1. 原始 BC 已直接学习接管动作

原始 `rlinf/workers/actor/fsdp_rlt_ac_policy_worker.py:124`：

```python
bc_target = torch.where(human_mask[..., None], action_chunk, bc_ref_chunk)
bc_error = torch.mean(torch.square(pi_chunk - bc_target), dim=-1)
bc_loss = torch.mean(bc_error)
```

即有接管时以人的实际动作作目标，无接管时以 VLA 参考作目标。它仍同时
优化 `-q_weight * Q + bc_weight * BC`，并非纯监督学习。

当前工作区的 `_bc_metrics` 则是 `mean(pi_chunk**2)`，没有使用传入的
actions 或 intervene_flags。Q 路径仍会使用接管数据；丢失的是 BC 的直接
接管监督通道，不是接管数据完全没有进入训练。

执行两份源码的实际 `_bc_metrics` 做了一个标量方向检查：actor 和参考为
零，接管动作 X=-0.2，10 步、7 维。原始方法有接管时 loss=0.00571429，
第一个 X 输出的梯度为 +0.00571429，梯度下降会向负 X 学习；无接管时为零。
当前工作区不论是否接管，loss 和该梯度都为零。这里数值是示意动作单位，
不能直接当作真机物理位移。

此前将零残差 BC 描述成原版设计不准确。离线报告中的原方法基线实际上是
当前改版，不是本文件中识别出的原始条件 BC。

## 2. 动作语义不同，不能原样粘贴 loss

原始 `rlinf/algorithms/rlt/route.py:130` 直接选择 actor 输出或 VLA 输出；
其 Franka 环境将 XYZ/RPY 当作缩放后的位移/旋转增量执行。critic 直接读取
环境动作。当前项目则输出相对 VLA 的归一化残差，再组装成绝对末端目标，
critic 也改成了残差输入。

因此在当前实现恢复条件 BC 时，应先把人的绝对动作转换到与 actor 一致的
残差空间，再用 human_mask 选择目标。XYZ 示例：人的目标比 VLA 的 X 小
4 mm，而残差尺度为 20 mm，则接管 X 残差目标应为 -0.2；未接管时为零。
RPY 需要周期角度差和一致的安全处理，不能直接拿绝对欧拉角与 tanh 残差
相减。是否只监督 XYZ 应作为任务适配实验，而不是称为完整复刻原始 loss。

## 3. 原始 replay 还会在接管时改写参考

原始 `rlinf/algorithms/rlt/transition.py:74` 在保存 current observation 前，
会用接管动作替换对应槽位的 ref_chunk。当前残差改版已移除这一步。

这也不能直接照搬：若先把参考替换成人的动作，再计算“人类动作减参考”，
残差会变成零，丢掉希望学习的修正。做原始目标的残差适配时，应保留真实
VLA 参考，并把人类动作作为训练目标另存。

## 4. 参数需要在相同动作/损失尺度下比较

提供的真机配置为 `bc_weight=5, q_weight=0.1, reference_dropout_prob=0.5`。
当前配置为 `0.3, 0.5, 0.5`。原来的 BC 是环境动作误差，当前是归一化残差
大小；条件 mask、维度平均和动作尺度也有影响，不能直接把旧参数复制过来。

下一轮实验应先在相同权重和安全处理下比较：当前零残差 BC、按原始语义
适配的条件 BC，以及仅 XYZ 的条件 BC。条件 BC 是“接管时学人、未接管时
跟参考”，与之前建议的“全部样本零残差正则 + 额外人类监督”也不完全相同。
确认目标语义后再扫描权重，避免一开始就同时改变损失和强度。

本次只检查原始目录，没有覆盖任何原始代码或机器人配置。这里只确认实现
差异及梯度行为，不据此宣称原始版本已在当前插入任务上验证成功。
