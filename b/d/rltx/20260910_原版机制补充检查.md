## 本次复用时补齐的问题

1. 原版 SAC checkpoint 只保存/恢复普通 replay，不包含 demo buffer。
   当前增加独立 demo checkpoint，恢复优先使用它；旧 checkpoint 可按显式
   配置从当前 rank 的可用 replay 窗口提取接管片段。已有显式加载的示范池
   不会被旧 replay 重复填充。
2. 原版 dataset 在示范池未就绪时一直循环等待，同步 runner 无法继续采集。
   当前同步 RLT 在各 rank 示范数量未达到门槛时返回采集阶段。
3. 原版虽然使用 randint 有放回采样，却把请求数截为池内样本数，小池会
   破坏设定的 batch 大小和 1:1 混合比例。当前保留请求数。
4. 内存缓存淘汰旧轨迹后，原 checkpoint 索引仍可能包含未写出的文件。
   当前 checkpoint 元数据/索引只描述实际写出的轨迹；恢复还会使旧采样
   窗口缓存失效。这同样提高普通 replay 的 checkpoint 一致性。

200 是示范缓存和采样窗口上限，不是永久保留所有历史示范。没有新接管时
示范不会被普通 rollout 挤掉；有超过 200 条新示范时，旧示范仍会退出窗口。
auto_save=False 时，持久化以定期 checkpoint 为准。

## 值得继续做，但本次未直接改的实验

### 优先：恢复 critic 对实际动作含义的一致表达

原版 critic 直接读取其环境动作；当前 critic 读取相对 VLA 的归一化残差，
但其 state 仍只有 z_rl 与 proprio，没有显式 ref_chunk。相同残差在不同
VLA 参考下可对应不同的机械臂目标。因此值得比较：给 critic 加入参考，
或让 critic 读取统一安全投影后的实际目标动作并做适当归一化。

这属于当前残差改版的适配问题，不是原版已经提供的现成开关，也还没有
证明是学习失败的原因。z_rl/proprio 可能已包含部分参考相关信息；增加
输入是否有收益必须实验。改变 critic 输入会影响旧权重兼容性，不能当作
一次普通配置修改。在线执行与 learner 的安全裁剪语义也需要先统一。

### 其次：普通 replay 的 30 与原版 200 做对照

独立示范池解决人类动作不被自主数据挤掉，但 Q 仍需要足够的成功和失败
经验。主 replay 扩大到 200 可能保留更丰富的经验，也会增加旧策略数据
占比。应在相同示范池与训练次数下比较 30/200，不能把“更大”直接等同于
“更好”。本次保持 30，避免同时改变多个因素。

### 再次：利用已有调度控制 Q 介入时机

可以比较先训练 critic/BC、再逐步提高 Q 权重的已有调度功能，但目前
BC=5/Q=.1 对 Q=0 的离线验证没有显示额外动作拟合收益。先确认 Q 的动作
表达与实际执行一致，再测试调度，比仅增加 Q 系数更有依据。

## 不宜照搬的部分

- 原版选择 actor 或 VLA 直接输出，当前为 VLA 加残差；不能直接替换路由。
- 原版接管时改写 ref_chunk；残差方案照搬会让“人的动作减参考”变成零。
- 原版 `_get_ref_chunk` 也直接使用保存的参考，并没有解决当前绝对 XYZ/
  Euler 输入的归一化问题。归一化仍需保证训练、推理、旧数据一致。
- 不因原版有 async/CrossQ/其他任务配置就默认启用；它们不是此次插入任务
  已验证有效的修复。
